# HomeMedicineBox 本地数据与后续 AI 方案

## 1. 文档目标

本文档定义当前本地优先 MVP 的数据口径，并说明后续接入拍照和 AI 识别时如何复用现有模型。

当前版本重点：

- 正式数据只保存在本地 SQLite。
- 页面通过 repository 读写，不直接操作数据库。
- 药品提醒基于本地批次计算。
- 手动就诊录入保持轻量，不要求用户填写医院、科室、医生姓名。

后续版本重点：

- 拍照和 AI 识别只作为录入增强。
- 识别结果存在则带入正式记录，不存在则不强制用户补填低频字段。

## 2. 设计原则

- `本地优先`：正式数据、提醒计算和页面列表都基于本地数据库。
- `少填优先`：手动表单只保留用户高频需要输入的字段。
- `识别增强`：医院、科室、医生等字段由后续识别能力自动带出。
- `可扩展`：保留字段和实体边界，为后续图片、AI 和同步预留空间。

## 3. 当前本地架构

| 模块 | 责任 |
| --- | --- |
| `AppDatabase` | Drift 数据库入口 |
| `drift_schema.dart` | 表结构定义 |
| `HomeRepository` | 本地数据读写、默认成员创建、级联删除 |
| `HomeStateController` | 页面状态快照和业务动作 |
| `ReminderEngine` | 根据 `MedicineBatch` 计算提醒状态 |

当前数据库保存：

- `FamilyMember`
- `MedicineItem`
- `MedicineBatch`
- `VisitRecord`
- `MedicalDocumentRecord`
- `RecognitionDraft`（底层保留，当前产品不暴露）
- `LocalImageAsset`（底层保留，当前产品不暴露）

## 4. 核心实体

### 4.1 FamilyMember

| 字段 | 说明 |
| --- | --- |
| id | 主键 |
| name | 成员名称 |
| relation | 成员关系 |
| isSystemDefault | 是否系统默认成员 |
| createdAt / updatedAt | 时间字段 |

首次启动自动创建系统默认成员“家庭共用”。

### 4.2 MedicineItem

| 字段 | 说明 |
| --- | --- |
| id | 主键 |
| memberId | 归属成员 |
| name | 药品名称 |
| genericName | 通用名，可选 |
| specification | 规格 |
| dosageForm | 剂型 |
| indication | 用途/适应症，可选 |
| storageNotes | 储存说明，可选 |
| source | manual / recognition |
| createdAt / updatedAt | 时间字段 |

### 4.3 MedicineBatch

| 字段 | 说明 |
| --- | --- |
| id | 主键 |
| medicineItemId | 所属药品 |
| quantity | 当前数量 |
| unit | 单位 |
| expiryDate | 有效期 |
| lowStockThreshold | 低库存阈值 |
| createdAt / updatedAt | 时间字段 |

提醒状态不落库，由 `ReminderEngine` 根据数量、阈值和有效期实时计算。

### 4.4 VisitRecord

| 字段 | 说明 |
| --- | --- |
| id | 主键 |
| memberId | 归属成员 |
| visitDate | 就诊日期 |
| diagnosisSummary | 诊断/问题摘要 |
| hospitalName | 医院名称，可选，主要由后续识别带出 |
| department | 科室，可选，主要由后续识别带出 |
| doctorName | 医生姓名，可选，主要由后续识别带出 |
| createdAt / updatedAt | 时间字段 |

当前手动新增就诊只写入：

- memberId
- visitDate
- diagnosisSummary

医院、科室、医生姓名不出现在手动表单中。

### 4.5 MedicalDocumentRecord

| 字段 | 说明 |
| --- | --- |
| id | 主键 |
| visitRecordId | 所属就诊事件 |
| documentType | 文档类型 |
| summary | 备注/文档摘要 |
| extractedText | 后续识别全文或摘要 |
| keyIndicators | 后续识别指标摘要 |
| imageAssetIdsJson | 后续图片引用 |
| source | manual / recognition |
| createdAt / updatedAt | 时间字段 |

当前用户填写备注/文档摘要时创建该记录。

## 5. 当前业务规则

### 5.1 药品

- 新增药品时创建 `MedicineItem` 和首个 `MedicineBatch`。
- 减少库存只更新批次数量，不删除批次。
- 删除药品时同步删除该药品的所有批次。
- 当前成员查看药品时，非“家庭共用”成员也能看到家庭共用药品。

### 5.2 就诊

- 新增就诊时只要求轻量字段。
- 如果备注/文档摘要为空，不创建 `MedicalDocumentRecord`。
- 删除就诊时同步删除关联 `MedicalDocumentRecord`。
- 医院、科室、医生姓名只有在数据存在时展示。

### 5.3 草稿

- 当前产品没有草稿箱入口。
- `RecognitionDraft` 作为后续 AI 识别技术准备保留。
- 当前正式列表、首页统计和提醒不依赖草稿。

## 6. 后续 AI 识别边界

### 6.1 药品识别

后续 `recognizeMedicine(images)` 可提取：

- 药品名称
- 通用名
- 规格
- 剂型
- 数量
- 单位
- 有效期
- 用途/适应症
- 储存说明

### 6.2 就诊文档识别

后续 `recognizeMedicalDocument(images)` 可提取：

- 就诊日期
- 诊断/问题摘要
- 备注/文档摘要
- 医院名称
- 科室
- 医生姓名
- 处方药列表
- 检查指标摘要

医院、科室、医生姓名属于“识别到了就展示”的增强字段，不作为用户手动录入的必要字段。

### 6.3 保存策略

- AI 识别结果必须由用户确认后保存正式记录。
- 识别字段缺失时，只要求用户补齐真正必要的字段。
- 对就诊记录而言，必要字段是成员、日期、诊断/问题摘要。
- 对药品而言，必要字段是成员、药名、规格、剂型、数量、单位、有效期、低库存阈值。

## 7. 技术验收

- 首次启动创建默认成员。
- 新增药品后可从 repository 读取。
- 药品批次提醒计算正确。
- 删除药品会删除批次。
- 新增就诊后可从 repository 读取。
- 手动新增就诊不需要医院、科室、医生姓名。
- `flutter analyze` 和 `flutter test` 通过。
