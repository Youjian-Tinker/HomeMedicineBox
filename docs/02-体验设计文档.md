# HomeMedicineBox MVP 体验设计文档

## 1. 设计目标

本文件将 PRD 中的产品范围翻译成页面结构、关键交互和状态规则，供 UI 设计、原型设计和研发联调使用。

平台说明：

- 产品目标平台为 iPhone 和 Android。
- 当前版本体验稿以 `iPhone 优先` 输出，Android 后续沿用相同信息架构、核心流程和字段定义，再按平台规范适配视觉与手势细节。
- 当前版本按 `本地单设备使用` 设计，不展示账号登录或数据同步入口；后续多设备同步版本再扩展相关交互。

设计原则：

- `低门槛`：先拍照，再确认，减少手动填写压力。
- `高可控`：AI 只辅助识别，最终保存必须由用户确认。
- `本地可信`：每个关键页面都要让用户知道数据留在本机。
- `家庭导向`：成员切换应该足够明显，避免串档。

## 2. 一级结构

当前版本采用底部导航 + 顶部成员切换的结构，适合作为 iPhone 首发方案；Android 版本延续相同一级结构，按平台导航规范调整视觉组件。

| 一级入口 | 目标 | 关键内容 |
| --- | --- | --- |
| 首页 | 快速了解家庭健康资料状态 | 提醒卡片、最近记录、快捷操作、待确认草稿 |
| 药品 | 管理家庭药箱 | 列表、筛选、批次、详情、编辑 |
| 就诊档案 | 沉淀医院资料 | 时间线、事件详情、文档查看、补录 |
| 设置 | 管理权限和说明信息 | 安全、通知、隐私、AI 说明 |

全局固定能力：

- 顶部成员切换器。
- 全局“拍照录入”入口。
- 待确认草稿状态入口。

## 3. 全局交互规则

### 3.1 成员切换

- 顶部显示当前成员名称。
- 点击后以抽屉或底部弹层形式展示所有成员。
- 默认存在一个系统成员：`家庭共用`，用于归档全家通用药品。
- 切换成员后：首页、药品、就诊档案都联动刷新。

### 3.2 全局拍照入口

- 首页显式展示两个主按钮：`拍照录药`、`新增就诊记录`。
- 药品页和就诊页也分别保留对应新增入口，避免用户必须返回首页。

### 3.3 草稿规则

- 所有 AI 识别结果统一先进入草稿态。
- 草稿态展示字段置信程度、缺失项、原图预览。
- 草稿未确认前，不出现在药品正式列表或就诊正式时间线中。

### 3.4 状态标签体系

| 场景 | 状态 | 展示规则 |
| --- | --- | --- |
| 药品 | 正常 / 即将过期 / 已过期 / 库存不足 / 已用完 | 在列表和详情中均展示 |
| 草稿 | 待确认 / 识别失败 / 待补充 / 已放弃 | 只在草稿箱和新增流程中展示 |
| 就诊事件 | 已建档 / 有待补资料 | 在就诊时间线和详情中展示 |

## 5. 核心流程设计

### 5.1 拍照录药

1. 用户点击 `拍照录药`。
2. 进入成员选择，默认带出当前成员。
3. 打开拍照页，提示拍摄药盒正面、规格面或说明单。
4. 拍摄后进入识别中间态，显示上传与识别进度。
5. 识别完成后进入药品草稿确认页。
6. 用户修改字段并保存，系统生成药品记录和药品批次。

关键交互要求：

- 支持补拍第二张或第三张图片。
- 识别中断时，可改为手动录入。
- 保存前必须提示当前成员归属，避免录错对象。

### 5.2 新增就诊记录

1. 用户点击 `新增就诊记录`。
2. 选择成员。
3. 进入文档拍摄页，提示选择文档类型或允许自动判断。
4. 拍摄单据后进入识别中间态。
5. 识别完成后进入就诊草稿确认页。
6. 用户确认本次就诊日期、医院、科室、诊断结果、文档归类后保存。

关键交互要求：

- 一次就诊可连续补拍多个文档。
- 允许把多张图片归到同一次就诊事件下。
- 处方药可在确认页被标记为“同步加入药箱”或“仅保留在病历中”。

### 5.3 日常查看与提醒处理

1. 用户打开应用进入首页。
2. 首页优先展示即将过期和库存不足的药品卡片。
3. 点入卡片后跳转到对应筛选结果的药品列表。
4. 用户可在详情中更新库存、删除记录或查看原图。

## 6. 页面方案

### 6.1 首页

| 模块 | 设计说明 |
| --- | --- |
| 顶部成员切换 | 当前成员名称 + 下拉切换入口 |
| 今日提醒 | 即将过期、已过期、库存不足三类卡片 |
| 快捷操作 | 拍照录药、新增就诊记录 |
| 最近新增 | 最近 3 条药品记录和最近 3 次就诊事件 |
| 草稿入口 | 展示待确认草稿数量和最近更新时间 |

页面状态：

- 空状态：引导先创建成员并录入第一条药品或就诊记录。
- 有提醒状态：提醒卡片置顶显示。
- 无提醒状态：展示“当前没有紧急提醒”与快捷操作。

### 6.2 药品列表页

| 模块 | 设计说明 |
| --- | --- |
| 搜索框 | 按药名搜索 |
| 筛选器 | 状态、成员、分类 |
| 药品列表 | 药名、规格、剩余数量、最近有效期、状态标签 |
| 新增入口 | 悬浮按钮或顶部按钮 |

列表交互：

- 点击列表项进入药品详情。
- 左滑或长按可快速执行删除、标记已用完。
- 列表排序默认按提醒优先级，再按最近更新排序。

### 6.3 药品草稿确认页

必填字段：

- 归属成员
- 药品名称
- 规格
- 剂型
- 数量
- 有效期

辅助字段：

- 用途/适应症
- 储存说明
- 备注

交互规则：

- 缺失必填字段时，保存按钮不可点击。
- 识别置信度较低的字段使用弱提醒样式提示复核。
- 支持“重新识别”“改为手动录入”“放弃草稿”。

### 6.4 药品详情页

| 模块 | 设计说明 |
| --- | --- |
| 基本信息 | 药名、规格、剂型、归属成员 |
| 批次信息 | 每个批次的数量、有效期、状态 |
| 图片区域 | 查看药盒或说明单原图 |
| 操作区 | 编辑、减少库存、标记已用完、删除 |

交互规则：

- 批次按有效期升序展示。
- 库存更新时优先扣减最早过期批次。
- 删除前需二次确认并提示会同步删除原图。

### 6.5 就诊档案列表页

| 模块 | 设计说明 |
| --- | --- |
| 时间线 | 按日期倒序展示就诊事件 |
| 筛选器 | 成员、日期、文档类型 |
| 事件卡片 | 日期、医院/科室、诊断摘要、文档数量 |
| 新增入口 | 新增就诊记录 |

页面规则：

- 事件卡片应一眼看出“看的是谁、什么时候、在哪就诊、结论是什么”。
- 若事件存在待补充文档，卡片展示“待补资料”标签。

### 6.6 就诊草稿确认页

必填字段：

- 归属成员
- 就诊日期
- 文档类型
- 诊断结果摘要

建议字段：

- 医院名称
- 科室
- 医生姓名
- 处方药列表
- 关键检查指标
- 备注

交互规则：

- 同一轮拍摄可生成多个文档草稿，确认页按文档分组展示。
- 用户可把多个文档合并到同一次就诊事件。
- 处方药同步入药箱前，必须允许用户逐项勾选。

### 6.7 就诊详情页

| 模块 | 设计说明 |
| --- | --- |
| 事件摘要 | 成员、日期、医院、科室、诊断结果 |
| 文档列表 | 处方单、检查报告、诊断书 |
| 原图预览 | 支持放大查看 |
| 延伸信息 | 处方药、关键指标、补充备注 |
| 操作区 | 编辑、追加文档、删除 |

### 6.8 草稿箱

草稿箱用于承接所有“拍完照但还没正式入库”的内容。

列表项需要包含：

- 草稿类型：药品 / 医疗文档
- 归属成员
- 最近更新时间
- 当前状态：待确认 / 待补充 / 识别失败
- 快捷操作：继续处理 / 删除

草稿箱规则：

- 首页只显示数量和最近 1 条草稿摘要。
- 完整草稿箱支持按类型和状态筛选。

### 6.9 设置页

设置页包含以下分组：

- 安全与解锁：生物识别或设备密码验证说明。
- 通知设置：过期提醒、库存提醒开关。
- 权限管理：相机、相册、通知。
- AI 识别说明：第三方识别提示、失败说明。
- 隐私说明：本地存储范围、删除机制、当前版本不启用数据同步说明。

## 7. 空状态与异常流

### 7.1 空状态

| 页面 | 空状态文案方向 |
| --- | --- |
| 首页 | 还没有健康资料，先录入第一盒药或第一次就诊记录 |
| 药品列表 | 当前成员还没有药品，点击拍照录入 |
| 就诊档案 | 当前成员还没有就诊记录，点击新增就诊记录 |
| 草稿箱 | 暂无待确认草稿 |

### 7.2 异常流

| 场景 | 处理方式 |
| --- | --- |
| 无网络 | 识别前提示当前无法连接识别服务，支持转手动录入 |
| 识别失败 | 保留原图，提示补拍或手动填写 |
| 权限拒绝 | 明确说明为什么需要权限，并跳转系统设置 |
| 保存失败 | 说明是字段缺失还是本地存储异常，不丢失草稿 |

## 8. 提醒机制设计

首页与药品模块统一使用以下提醒逻辑：

- `即将过期`：默认 30 天内到期。
- `已过期`：当前日期超过有效期。
- `库存不足`：低于用户手动设定阈值，若未设置则按默认 1 盒/1 单位处理。

展示原则：

- 首页看“最需要处理的事”，强调数量和动作入口。
- 列表页看“具体是哪条记录”，强调状态标签和筛选。
- 详情页看“怎么处理”，强调批次与库存变更。

## 9. 设计交付建议

设计师继续出图时，优先完成以下页面：

1. 首页
2. 药品列表页 + 药品详情页
3. 拍照录药流程 + 药品草稿确认页
4. 就诊档案列表页 + 就诊详情页
5. 新增就诊记录流程 + 就诊草稿确认页
6. 草稿箱
7. 设置页

交互原型必须覆盖：

- 首次启动
- 成员切换
- 药品录入成功
- 就诊录入成功
- 识别失败转手动录入
- 删除记录
