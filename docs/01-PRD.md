# HomeMedicineBox MVP 产品需求文档（PRD）

## 1. 文档概览

| 项目 | 内容 |
| --- | --- |
| 产品名称 | HomeMedicineBox |
| 当前版本 | 本地优先 MVP |
| 目标平台 | iPhone 优先，后续 Android |
| 当前实现策略 | 先手动录入和本地持久化，后续再接拍照与 AI 识别 |

## 2. 产品定位

HomeMedicineBox 是一款面向家庭管理者的本地健康资料管理应用，用来记录家庭常备药、库存、有效期和就诊资料。当前 MVP 不做账号、云同步、拍照识别和医疗建议，优先把本地录入、查看、编辑、删除和提醒计算打通。

一句话描述：

> 用一部手机管理家里的药箱和关键就诊记录。

## 3. 当前 MVP 目标

- 用户可以手动新增药品和批次，并在应用重启后继续看到。
- 用户可以手动新增就诊记录，并在应用重启后继续看到。
- 首页基于真实本地数据展示过期、临期和低库存统计。
- 支持成员切换，默认提供“家庭共用”成员承载通用药品。
- 支持药品详情、编辑、减少库存、删除。
- 支持就诊详情和删除。

## 4. 当前 MVP 范围

### 4.1 P0 功能

| 模块 | 功能 |
| --- | --- |
| 本地数据 | 使用 Drift / SQLite 保存正式记录 |
| 家庭成员 | 首次启动自动创建“家庭共用” |
| 药品 | 新增、列表、详情、编辑、减少库存、删除 |
| 批次 | 新增药品时创建首个批次，批次用于库存和有效期提醒 |
| 就诊 | 轻量新增、列表、详情、删除 |
| 首页 | 成员切换、提醒统计、最近药品、最近就诊 |
| 设置 | 隐私、本地存储和后续 AI 说明 |

### 4.2 当前不做

- 不做草稿箱。
- 不做拍照、相册、图片管理。
- 不接 AI。
- 不做账号、家庭协作、云同步。
- 不做用药计划、服药打卡、医疗建议。
- 不要求用户手动填写医院、科室、医生姓名。

## 5. 药品需求

### 5.1 新增药品

用户在药品页新增药品，字段如下：

必填：

- 成员
- 药品名称
- 规格
- 剂型
- 数量
- 单位
- 有效期
- 低库存阈值

可选：

- 用途/适应症
- 储存说明

保存后创建一条 `MedicineItem` 和一条 `MedicineBatch`。

### 5.2 药品列表和详情

- 药品列表读取本地数据库。
- 当前成员可以看到自己的药品；非“家庭共用”成员也能看到家庭共用药品。
- 详情展示基本信息、批次、库存、有效期和提醒状态。
- 提醒状态包括：正常、即将过期、已过期、库存不足、已用完。
- 支持减少库存。
- 支持编辑药品基础字段。
- 删除药品前二次确认，并同步删除批次。

## 6. 就诊需求

### 6.1 手动新增就诊

手动新增就诊记录只保留用户真正需要输入的轻量字段。

必填：

- 成员
- 就诊日期
- 诊断/问题摘要

可选：

- 备注/文档摘要

保存后创建 `VisitRecord`。如果填写备注/文档摘要，同时创建 `MedicalDocumentRecord`。

### 6.2 不要求手动填写的信息

以下字段不出现在当前手动表单中：

- 医院名称
- 科室
- 医生姓名

这些字段只作为后续“诊断报告 / 处方 / 检查报告识别”可能带出的结构化信息。如果识别结果里有，就在详情页展示；如果没有，不显示占位，也不要求用户补充。

### 6.3 就诊列表和详情

- 就诊列表读取本地数据库。
- 列表按当前成员过滤，不混入其他成员记录。
- 列表主信息展示诊断/问题摘要，副信息展示就诊日期；如果未来识别带出医院或科室，可追加展示。
- 详情展示就诊日期、诊断/问题摘要、备注/文档摘要。
- 如果记录中存在识别带出的医院、科室、医生姓名，详情页只读展示。
- 支持删除就诊记录，并同步删除关联文档。

## 7. 首页需求

- 展示当前成员切换。
- 展示真实数据统计：
  - 即将过期
  - 已过期
  - 库存不足
- 展示最近药品。
- 展示最近就诊。
- 首页不展示草稿入口或草稿数量。

## 8. 数据要求

- 正式数据保存在本机 SQLite。
- App 重启后药品、批次和就诊记录仍然存在。
- 首次启动自动创建默认成员“家庭共用”。
- 草稿相关底层模型可以保留给后续识别能力，但当前产品不暴露草稿箱和草稿流程。

## 9. 后续 AI 识别规划

后续接入拍照和 AI 后，识别只负责减少录入成本，不能替代用户确认。

药品识别可带出：

- 药品名称
- 规格
- 剂型
- 数量
- 有效期
- 用途/储存说明

就诊文档识别可带出：

- 就诊日期
- 诊断/问题摘要
- 文档摘要
- 医院名称
- 科室
- 医生姓名
- 检查指标
- 处方药

识别字段如果存在则展示和保存；不存在时不强迫用户补充非必要字段。

## 10. 验收标准

- `flutter analyze` 通过。
- `flutter test` 通过。
- iOS 模拟器 debug build 通过。
- 用户可以新增药品，退出重启后仍能看到。
- 用户可以新增就诊记录，退出重启后仍能看到。
- 用户无法在当前 App 中看到草稿入口。
- 手动新增就诊时不会出现医院、科室、医生姓名输入项。
