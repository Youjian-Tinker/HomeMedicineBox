# HomeMedicineBox 工程落地说明

本文件定义 HomeMedicineBox 从需求文档进入正式 Flutter 产品化实现的工程口径。当前目标不是搭建临时演示或功能性测试项目，而是直接落地可持续迭代的本地优先移动应用。

## 1. 工程目标

- 使用 `Flutter` 同时保留 iOS 和 Android 交付路径。
- 首版按 iPhone 优先完成体验和真机验收，Android 沿用同一信息架构和业务模型。
- 正式数据和图片优先保存在本机，v1 不接账号、不做同步、不接自建服务器。
- AI 识别通过可配置云端服务接入，未配置或失败时不阻断手动录入。
- 保留少量核心自动化测试，覆盖最容易造成数据污染或提醒错误的业务逻辑。

## 2. 技术选型

| 层级 | 选型 | 说明 |
| --- | --- | --- |
| 应用框架 | Flutter | 跨端 UI 与业务代码复用 |
| 状态管理 | Riverpod | 明确业务状态、便于测试 |
| 路由 | go_router | 管理首页、药品、就诊、草稿、设置等入口 |
| 本地结构化数据 | Drift / SQLite | 正式实现阶段作为本地数据库方案 |
| 图片存储 | App 私有文件目录 | 药品、就诊文档、草稿图片均保留本地引用 |
| AI 识别 | 可配置 HTTP 服务 | 不硬编码服务商，不提交 API Key |
| 基础测试 | flutter_test / test | 只覆盖核心领域逻辑和失败回退 |

## 3. 模块边界

| 模块 | 责任 |
| --- | --- |
| `domain` | 家庭成员、药品、批次、就诊、草稿、图片等核心模型与业务规则 |
| `data` | 本地存储、图片索引、AI 识别服务、仓储实现 |
| `app` | 路由、主题、全局状态装配 |
| `features` | 首页、药品、就诊档案、草稿箱、设置等页面 |
| `test` | 草稿转正、提醒计算、图片清理、AI 失败回退等基础自动化测试 |

## 4. 落地顺序

1. 生成 Flutter 工程并保留 `ios/`、`android/` 平台目录。
2. 建立领域模型和核心服务，先稳定草稿、提醒、删除清理等业务规则。
3. 实现首页、药品、就诊档案、草稿箱、设置页的 P0 流程。
4. 接入本地数据库和 App 私有文件目录，替换临时内存状态。
5. 接入可配置 AI 服务，确保失败时保留草稿并允许手动录入。
6. 执行基础自动化测试和真机验收清单。

## 5. 稳定性策略

不建设完整端到端功能自动化测试套件。稳定性通过以下组合保证：

- 核心业务规则使用基础自动化测试覆盖。
- 相机、权限、通知、生物识别、本地文件读写使用真机验收。
- 无网络、AI 失败、字段缺失、本地写入失败等异常路径必须保留用户数据和草稿。
- 删除正式记录时必须清理无引用图片，并刷新本地提醒计算。

## 6. 真机验收清单

- iPhone：拍照录药、新增就诊、查看详情、修改库存、删除记录。
- Android：基础启动、同等信息架构、手动录入和列表查看。
- 异常流：无网络、AI 未配置、AI 超时、权限拒绝、通知关闭、生物识别不可用。
- 数据持久性：应用重启后正式记录、草稿和图片引用仍可读取。
