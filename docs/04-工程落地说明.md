# HomeMedicineBox 工程落地说明

本文件定义当前本地优先 MVP 的工程口径。当前目标是先完成可运行、可重启持久化的 Flutter 应用，不先接相机、AI、账号或云服务。

## 1. 工程目标

- 使用 Flutter 保留 iOS 和 Android 交付路径。
- 当前以 iPhone 模拟器和 iOS debug build 验收为主。
- 正式数据保存在本机 SQLite。
- 手动录入先可用，后续识别能力只作为录入增强。
- 保留基础测试覆盖本地数据和提醒规则。

## 2. 技术选型

| 层级 | 选型 | 说明 |
| --- | --- | --- |
| 应用框架 | Flutter | 跨端 UI 与业务代码复用 |
| 状态管理 | Riverpod | 管理页面快照和业务动作 |
| 路由 | go_router | 管理首页、药品、就诊、设置入口 |
| 本地结构化数据 | Drift / SQLite | 保存成员、药品、批次、就诊和文档摘要 |
| 基础测试 | flutter_test / test | 覆盖 repository、提醒计算和关键 widget |

## 3. 模块边界

| 模块 | 责任 |
| --- | --- |
| `domain` | 领域模型、提醒计算、图片清理、后续识别草稿规则 |
| `data/local` | Drift schema、数据库、repository |
| `app` | 路由、主题、全局 provider 和状态控制器 |
| `features/home` | 首页统计、最近药品、最近就诊 |
| `features/medicines` | 药品列表、新增、详情、编辑、库存减少、删除 |
| `features/visits` | 就诊列表、轻量新增、详情、删除 |
| `features/settings` | 本地隐私和后续能力说明 |
| `test` | 本地持久化、提醒、删除级联、基础 UI 启动 |

## 4. 当前实现口径

### 4.1 药品

- 手动新增创建 `MedicineItem` 和首个 `MedicineBatch`。
- 批次承担库存和有效期提醒计算。
- 删除药品时先删批次，再删药品。

### 4.2 就诊

- 手动新增只接收成员、就诊日期、诊断/问题摘要、备注/文档摘要。
- `hospitalName`、`department`、`doctorName` 字段仍保留在模型和数据库中，作为后续诊断报告识别结果的承载字段。
- 当前手动表单不展示医院、科室、医生姓名。
- 详情页仅在这些字段有值时展示，不显示空占位。

### 4.3 草稿

- 当前产品不提供草稿箱和草稿流程。
- 识别相关底层模型和测试可以保留，作为后续 AI 接入的技术准备。
- 当前 App 路由和底部导航不暴露草稿入口。

## 5. 落地顺序

1. 完成本地数据库和 repository。
2. 打通药品新增、读取、编辑、删除和提醒。
3. 打通就诊轻量新增、读取、详情和删除。
4. 首页全部改为真实数据。
5. 清理不必要的手动字段，降低录入负担。
6. 后续再接相机、图片和 AI 识别。

## 6. 稳定性策略

- 使用 `flutter analyze` 保证静态检查通过。
- 使用 `flutter test` 覆盖核心逻辑。
- 使用 `flutter build ios --simulator --debug` 验证 iOS 工程可构建。
- 对删除动作做二次确认。
- 对正式数据删除执行关联数据清理。

## 7. 验收清单

- 底部导航只有：首页、药品、就诊、设置。
- 首次启动自动创建“家庭共用”。
- 新增药品后重启 App 数据仍存在。
- 减少库存后提醒状态正确变化。
- 删除药品会删除批次。
- 新增就诊后重启 App 数据仍存在。
- 手动新增就诊没有医院、科室、医生姓名输入项。
- 详情页仅在存在识别字段时展示医院、科室、医生姓名。
