# HomeMedicineBox 工程落地说明

本仓库已从纯文档状态升级为 `Flutter 本地优先 MVP 脚手架`，当前重点是把架构边界、领域模型和主要页面形态先落到代码里。

## 当前已落地内容

- 根目录已按 Flutter 应用组织：`pubspec.yaml`、`analysis_options.yaml`、`lib/`、`test/`
- 已抽出核心边界：
  - `LocalRepository`
  - `DraftRepository`
  - `RecognitionProvider`
  - `ImageStore`
  - `ReminderEngine`
  - `SecurityGate`
- 已建立核心领域模型：
  - `FamilyMember`
  - `MedicineItem`
  - `MedicineBatch`
  - `VisitRecord`
  - `MedicalDocumentRecord`
  - `RecognitionDraft`
  - `LocalImageAsset`
  - `ReminderItem`
- 已提供本地假实现与种子数据，便于 UI 联调
- 已完成代表性页面：
  - 首页
  - 药品列表 / 详情
  - 就诊档案列表 / 详情
  - 草稿箱 / 草稿详情
  - 设置页

## 为什么现在是“蓝图 + 假实现”

当前环境没有安装 `Flutter SDK`，因此无法：

- 运行 `flutter create .` 生成 `ios/`、`android/`
- 运行 `flutter pub get`
- 运行 `build_runner` 为 Drift 生成代码
- 执行 `flutter test`

为了不阻塞工程落地，当前版本先把最关键的架构边界和 UI 骨架写成明确代码，等本机安装 Flutter 后即可继续。

## 下一步建议

1. 安装 Flutter SDK，并在仓库根目录执行 `flutter create . --platforms=ios,android`
2. 执行 `flutter pub get`
3. 把 `lib/src/data/local/drift/home_medicine_drift_blueprint.dart` 迁移为真正的 Drift table/database 定义
4. 使用 `dart run build_runner build` 生成 Drift 代码
5. 把 `data/mock/` 逐步替换为真实本地实现：
   - Drift repository
   - File-system image store
   - local_auth security gate
   - flutter_local_notifications scheduler
   - 云端 AI + 本地 OCR fallback
